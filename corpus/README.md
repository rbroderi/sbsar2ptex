# Atomic node corpus

One small graph per Substance atomic node (and its main modes), each run on a
known test pattern. Substance's own render of each graph is the reference
("truth") the converter's output is compared against.

Everything here is our own: the patterns are generated by
`make_patterns.py`, and every graph holds only those patterns (embedded
Bitmap resources) and one atomic node. No Adobe library graph is referenced.

## Layout

| path | contents |
|---|---|
| `patterns/` | the 128 x 128 test patterns (see `make_patterns.py` for the exact formulas) |
| `sbs/<node>.sbs` | the source graph |
| `sbsar/<node>.sbsar` | the graph cooked by sbscooker (embeds the patterns it uses) |
| `truth/<node>/output.png` | sbsrender's render: 16-bit for grayscale outputs, 8-bit for color |
| `inventory.tsv` | node, category, filter, variant, inputs, outputs, cooked ok, rendered ok |
| `library_inventory.tsv` | the bundled library nodes (metadata only; see below) |

Node names are `a_<filter>_<c|g>_<variant>_<coded|noise>`: the filter, the
image type of its main inputs (color or grayscale), the parameter variant
(`default` is the node at default parameters) and the main pattern. The
default variant is run on both patterns, the other variants on the coded one.

## Patterns

- `coded_rgba`: R = 2x, G = 2y, B = R XOR G, A = 255. Every pixel is unique,
  so a sample's source position can be read back from its color.
- `noise_rgba`, `noise_gray`: xorshift32 bytes from a fixed seed.
- `coded_gray16`: 16-bit, v = (y * 128 + x) * 4, every pixel unique.
- `bumps16`: a smooth tileable 16-bit height, fed to warp and emboss
  gradient inputs and directional warp intensity.
- `mask`: binary disc and rectangle, fed to blend opacity and distance masks.
- `ramp_h`: a horizontal 8-bit ramp (spare, for gradient-map tests).

A node's first input of each image type takes the main pattern (coded or
noise), a second input of the same type takes the other one (so a blend's
source and destination differ), and role inputs take their role pattern.
Every Bitmap node is set to 16-bit output, so the nodes compute in 16-bit.

## Regenerating

Run from the repo root, with Substance 3D Designer installed at
`C:/Program Files/Adobe/Adobe Substance 3D Designer/` (`sbscooker.exe` and
`sbsrender.exe`; edit `DESIGNER` in `make_corpus.py` for another location):

```
python corpus/make_patterns.py corpus/patterns --size 128
uv run python corpus/make_corpus.py corpus --only atomic --size 128 --depth auto
uv run python corpus/check_truth.py corpus      # per-output stats, identity check
```

The graphs' own `$outputsize` default stays 8 (256 px); the truths are
rendered with `$outputsize@7,7`. Convert with `--size 7` to compare at
128 px, e.g. `uv run sbsar2ptex corpus/sbsar/<node>.sbsar --procedural
--experimental --size 7 -o <dir>`.

Each graph output gets a channel usage so the converter maps it to a
Material Maker slot: color outputs `baseColor` (then `emissive`),
grayscale ones `roughness` (then `metallic`, `ambientOcclusion`,
`opacity`, `height`). The inventory's outputs column shows it in brackets.

`make_corpus.py` uses `sbsar2ptex.probe`'s XML helpers, so it runs in the
project venv. `--steps gen,cook,render` and `--match SUBSTR` redo part of it.

The full-size working corpus (256 x 256 patterns, 16-bit truths, atomic and
library nodes) is built the same way without `--size 128 --depth auto`, into
a folder outside the repo.

## Deliberately excluded

- **Library nodes.** Their graphs and cooked .sbsar embed Adobe's library
  content, so they stay outside the repo. Only their names, categories,
  packages and input/output lists are listed in `library_inventory.tsv`
  (written by `scan_library.py` from Designer's bundled packages).
- **No Adobe package or library file** is copied here.
- **Value Processor**: its output is a value, not an image, so it has no
  graph here.
- Text, SVG and an empty FX-Map render black at default parameters (they
  need a font, an SVG resource or a pattern tree). They are kept as
  "does the node exist and stay black" cases; the FX-Map also has two
  pattern variants.
